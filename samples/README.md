# Sample email collections

These are fictional files for learning and demonstration. All domains are `.example`, public IP addresses use documentation ranges, and attachments are inert. The files can be opened in E-Trace without an email account.

## Which sample should I use?

| Sample | Choose it when | Contents |
| --- | --- | --- |
| [`quick-demo/`](quick-demo/README.md) | You want a first result in a few minutes | 14 EML files already extracted |
| [`realistic-41.zip`](realistic-41.zip) | You want a small case with ordinary mail and an invoice phishing scenario | 41 EML files in each labelled folder |
| [`complex-355.zip`](complex-355.zip) | You want overlapping mailboxes, routine traffic and several attack scenarios | 355 labelled EML files plus one duplicate acquisition in each labelled folder, representing 174 logical messages |

The ZIPs contain two folders with the same email bytes, `conformance/` and `intent/`, plus answer keys and historical result files. Ingest **only one** of those folders into a case. The duplicate acquisition in the larger archive has the same bytes as another file and records a second collection path.

## Run the 14-file quick demo

Follow the [README quick start](../README.md#get-started-from-github). Its `ingest` command points directly to `samples/quick-demo/`. The [scenario guide](quick-demo/README.md) explains which messages and relationships to inspect.

## Run the 41-file sample

Run these commands from the repository root in PowerShell after installing E-Trace. Use a new destination and case name if you have run them before:

```powershell
Expand-Archive -LiteralPath .\samples\realistic-41.zip -DestinationPath .\work\realistic-41
.\.venv\Scripts\python.exe -m etrace init .\work\realistic-41.db --name "Realistic sample"
.\.venv\Scripts\python.exe -m etrace ingest .\work\realistic-41.db .\work\realistic-41\etrace-realistic-corpus\conformance
.\.venv\Scripts\python.exe -m etrace analyze .\work\realistic-41.db
.\.venv\Scripts\python.exe -m etrace serve .\work\realistic-41.db
```

Open <http://127.0.0.1:8765> and inspect the timeline, graph and diagnostics. Stop the server with `Ctrl+C` before starting another sample on the same port.

## Run the 355-file sample

```powershell
Expand-Archive -LiteralPath .\samples\complex-355.zip -DestinationPath .\work\complex-355
.\.venv\Scripts\python.exe -m etrace init .\work\complex-355.db --name "Complex sample"
.\.venv\Scripts\python.exe -m etrace ingest .\work\complex-355.db .\work\complex-355\etrace-complex-corpus\conformance
.\.venv\Scripts\python.exe -m etrace analyze .\work\complex-355.db --trusted-wrapper-host safelinks.mailprotect.example --organisation-domain halcyon-freight.example
.\.venv\Scripts\python.exe -m etrace serve .\work\complex-355.db
```

The wrapper host and organisation domain are fictional settings for this sample. They help E-Trace interpret its simulated Safe Links rewrites and suppress the company's own URL as a coordination signal. They should not be applied automatically to a real case.

On macOS or Linux, use `python3 -m zipfile -e samples/realistic-41.zip work/realistic-41` (or the complex archive) and replace `.\.venv\Scripts\python.exe` with `./.venv/bin/python` in the commands. Use forward slashes in paths.

## How these differ from evaluation data

The 41- and 355-file archives include answer keys produced from their scenarios. Those labels were written for an earlier rule definition and should not be used as current accuracy scores. The 14-, 77- and 269-message controlled evaluation tiers are generated by `evaluation/generate.py` outside the repository and scored by `evaluation/evaluate.py`. See [rules and evaluation](../docs/rules-and-evaluation.md) for the testing method and limitations.
